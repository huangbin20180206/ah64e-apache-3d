# AI 协作规约（AI-WORK-RULES）

> 本文件是对 2026-10-14 P4a~P4e 五批产出的实证复盘结论，对后续所有 AI 开发会话生效。
> 规约分三部分：①不可退化项（已做对，继续保持）②硬性约束（实证盲区，强制补齐）③交付 checklist（每批必过）。
> 违例即打回，不接受「下批补」。

## 一、不可退化项（实证做对的，固化为底线）

以下五项在 P4a~P4e 中零偏差执行，后续任何批次不许退化：

1. **数字编号模块制**：新模块选前缀即声明依赖顺序；app 代码零 `import`，单 IIFE 共享作用域。
2. **契约表与代码同批更新**：`docs/module-contracts.md` 的机读契约块，新增/改名/改 provides/depends 必须与代码同一批完成——构建拓扑检查以此表为输入，表滞后等于检查失效。
3. **构建门禁三道检查必须全绿才算交付**：拓扑检查（无反向引用/依赖≤契约）、DOM id 契约（template 与代码双向核对）、禁 import 检查。附 Exit Code 与产物体积。
4. **纯逻辑模块纪律**：84+ 编号的纯逻辑模块保持零 THREE、零 DOM；外部依赖（storage 等）构造注入；读不到/损坏/隐私模式一律降级不炸页面。
5. **性能预算制**：新增场景内容必须附同机位前后 draw call 对比表，增幅 ≤15%；新增视觉元素逐项声明 draw 数与是否投影。

## 二、硬性约束（实证盲区，2026-10-14 起强制）

### C1 交互改动必须过「用户旅程自查」

实证反例：`46-fpview` 鼠标下移=抬头（FPS 常识为下俯），靠用户反馈才发现；`test_fp_aim` 之后才补。

- 凡触及键盘/鼠标/触摸/界面反馈的改动，交付前必须在交付说明里写一段**用户操作路径**：用户手指怎么动 → 画面怎么应 → 对应哪个平台的肌肉记忆（引用具体平台惯例，如「FPS 惯例：鼠标上移=机头上仰」）。
- 方向类操作（鼠标 Y 轴、摇杆、滚轮、方向键）必须显式对照通用平台习惯，禁止「数学上等价就行」。
- 自检问题：「第一次玩的人，会预期相反的方向吗？」答不上来不许交付。

### C2 注释与代码同生共死

实证反例：`90-campaign` 注释「5 关解锁链」实际 6 关；`83-arcade` 文件头「成就 8 项」实际 10 项。功能加了、数字没改，双标（契约表同步了，注释没同步）。

- 改功能必改注释；注释中的计数（关卡数/成就数/模块数）必须与代码实际定义逐字对得上。
- 每个文件交付前 grep 自己的文件头注释段，核对描述与现实。
- 自检问题：「文件头注释描述的状态，和文件里的实际定义，还对得上吗？」

### C3 日志状态三档分明，禁模糊词

实证反例：CHANGES-p4d/p4e 写「未打包」，实际代码早已入 src 且构建通过——读者无法判断真实状态。

- 状态只能三选一标注：`代码已入 src` / `构建通过（Exit 0 + 体积）` / `全量回归已过（附 run_tests 结果）`。
- 禁用「未打包」「待整理」「基本完成」等不可验证词汇；CHANGES 只记录已发生事实，不写预期。
- 自检问题：「读者只看这句，能复现我描述的状态吗？」

### C4 测试分两层：契约层 + 体验层

实证反例：tests_pure 89 项全绿，但鼠标反向这种交互常识全部测试盲区——逻辑测试只证明「代码按设计运行」，不证明「设计让人用得舒服」。

- 契约层（现有，保持）：断言代码按设计运行。
- 体验层（新增）：交互类改动必须附体验自检项——方向直觉、反馈时效（操作到画面的延迟量级）、首次用户可发现性（不读说明能否发现该功能）。
- 新增交互没有体验层自检 = 该功能没写完，不许进交付。

### C5 每批交付附可核对数据（P4a~P4e 已做到，固化为规矩）

- build Exit Code、dist/index.html 体积及 delta、app 模块数、bundle_sha256、tests_pure 通过数、manifest 条数。
- 无数据批次 = 无交付。数据以命令实际输出为准，禁止手写估计值。

## 三、交付 checklist（每批改动最后一步，逐条打勾）

1. [ ] 拓扑 / DOM id / 禁 import 三道检查 Exit 0，产物体积已记录
2. [ ] module-contracts.md 契约块已同步（新增模块必入表，provides/depends 准确）
3. [ ] 所有触及交互的改动已附「用户操作路径」+ 方向对照说明
4. [ ] 改动文件的文件头注释与代码现实逐字核对过（尤其计数）
5. [ ] CHANGES 只用三档状态词，无模糊表述
6. [ ] 新增交互有体验层自检（方向/时效/可发现性至少一项）
7. [ ] manifest 无重复登记，新增测试与磁盘 test_*.py 双向核对一致
8. [ ] 纯逻辑模块保持零 THREE 零 DOM + 容错三件套
9. [ ] 性能敏感改动附 draw call 前后对比，增幅 ≤15%
10. [ ] 交付数据全部来自命令实际输出，无估计值

## 四、红线（违反即整体打回）

- 禁 `Math.random()`（视觉噪声一律走种子 `rnd()`，可复现是测试断言的前提）
- 禁外部 CDN / 禁 import（单文件产物形态不容破坏）
- 禁覆写他人批次已绿产的测试来「让测试通过」——测试失败先分级：环境已知失败（沙盒 rAF 类）须注明并在旧基线复证；真实失败必须修
- 禁顺手「改进」需求之外的代码（精准修改：每一行 diff 可追溯到本条需求）
