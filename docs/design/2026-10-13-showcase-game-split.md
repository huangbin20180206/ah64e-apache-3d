# P0 设计文档：展示 / 游戏 双模式拆分（2026-10-13）

## 0. 已定原则
- 开场两个入口：**展示**、**游戏**。核心功能分开，底层渲染、飞行、武器两边共用。
- 展示模式**保留**开火和靶场，定位为“演示 + 练手”，不计分、不失败。
- 视觉与界面整体从“玩具感”升级到写实军事风格。
- 游戏模式把现有全部关卡统一管理：章节、难度梯度、场景、任务、过关要求都由一张关卡表驱动。
- 设计决策由 Hark 负责，用户只做验收。

## 1. 现状诊断

### 1.1 结构
- 48 个模块，约 830KB。所有功能挤在右侧一个 246px 的面板里，分 6 节，可见控件 40 多个。
- 已有“展示 / 训练 / 任务”三个模式 chip，但只切换任务状态，界面和子系统并不隔离。
- 关卡定义有两套，各管各的：
  - 70-mission 的 7 个任务变体：标准、限时救援、受限弹药、压制防空、制空、城镇、峡谷
  - 90-campaign 的 6 关战役链，只用到 4 种变体；解锁条件是前一关达到 B 评级

### 1.2 视觉（实拍截图诊断）
| 问题 | 现象 | 方向 |
|---|---|---|
| 地面 | 草地是平铺噪声加零散黄色草片，像贴纸；沙漠是单一橙色平面 | 多层材质、起伏、远景过渡 |
| 地平线 | 地面在远处硬切进天空，没有远山、树线、大气透视 | 远景剪影 + 高度雾 |
| 灯光 | 黄昏沙漠下机腹搜索灯画出一大块过曝白色光锥 | 光锥强度随环境光衰减，白天关闭 |
| 天空 | 渐变天空，没有云 | 程序化云层，按时段调色 |
| UI | 全是同一种绿框 chip，层级平均，信息密度高，没有主次 | 改为 MFD（多功能显示器）风格，分页，主操作不超过 6 个 |
| 后处理 | 颗粒、色散默认偏重，画面发脏 | 降低默认值，展示模式更干净 |

## 2. 入口与模式结构
- 载入完成后进入**主菜单**：背景是电影机位缓慢环绕机体，左侧是标题，右侧两张大卡：
  - **展示 SHOWCASE**：“3D 机体 · 飞行 · 武器与机械”
  - **游戏 MISSIONS**：“13 关战役 · 当前进度 x/13 · 继续上次”
- 次要入口：设置（画质、音效、灵敏度、语言预留）、操作说明。
- URL 直达：`#show`、`#play`、`#play/3-1`（直进某关，需已解锁）。
- 两个模式都用 Esc 呼出菜单：继续 / 返回主菜单 / 设置。
- 切换模式时，不用的子系统整体卸载（dispose），不只是隐藏。

## 4. 展示模式设计

### 4.1 界面
- 默认画面干净：只有左上角标题和底部一条分页标签栏。点击标签后，从右侧滑出对应的分页面板。
- 分页：
  1. **机体**：涂装、分解视图滑杆、部件标签、线框、自动旋转、经典机位
  2. **飞行**：启旋 / 起飞 / 第一人称；航线展示（4.2）
  3. **环境**：场地 × 时段 × 天气，做成带缩略图的预设卡，另外 6 个一键组合场景
  4. **武器**：挂载开关、开火、装填、靶场练手（显示/重置靶场、空中靶、绞车），可选秒表练习
  5. **知识**：武器与机械知识卡（4.3）
- 视觉语言：深色半透明面板、1px 细线、单色绿为主色、琥珀色做警示；等宽数字配中文黑体；动效克制。

### 4.2 飞行展示航线（6 条，每条 40–60 秒，自动驾驶 + 电影机位）
| 航线 | 场地 / 时段 | 看点 |
|---|---|---|
| 晨间出勤 | 停机坪 · 正午 | 启旋、下洗、起飞、绕场 |
| 草原低空 | 草地 · 白天 | 草浪压痕、贴地高速通场 |
| 沙漠黄昏 | 沙漠 · 黄昏 | brownout、侧光剪影 |
| 湖面掠水 | 湖面 · 黄昏 | 倒影、涟漪、水花 |
| 城镇巡逻 | 城镇 · 白天 | 楼间穿行、长弓雷达扫描 |
| 峡谷穿越 | 峡谷 · 黄昏 | 贴谷底蛇行、崖顶露头 |
- 任何时候按任意键都能接管驾驶，Esc 回到航线菜单。
- 现有“一键导览”并入，作为“精选 60 秒”。

### 4.3 知识库（10 张卡）
每张卡包含：一句话定位、3–5 条关键参数、一个讲原理的小段落，并联动机体（镜头飞到对应部件、高亮、可选分解）。

1. M230 30mm 链炮（随动炮塔、射速、弹舱）
2. AGM-114 地狱火（半主动激光 / 毫米波制导、射程、发射方式）
3. Hydra 70 火箭与 M261 火箭巢
4. AN/APG-78 长弓火控雷达（桅顶毫米波雷达、发射后不管）
5. TADS/PNVS 目标捕获与夜视（机鼻转塔）
6. T700-GE-701D 发动机
7. 主旋翼与尾桨（四片桨叶、交错尾桨、桨毂）
8. 串列座舱（前座射手、后座飞行员、防弹玻璃）
9. 生存性设计（抗坠毁、装甲、自封油箱）
10. 机载自卫（RWR 雷达告警、干扰弹）
- 所有参数在 P4 编写时逐条对照公开资料核实，并注明来源。

### 4.4 场景与视觉提升清单
- 停机坪：真实机场停机坪布局（滑行线、系留点、照明桅杆、机库、油车），边缘向草地过渡
- 草地：近景实例化草加地形起伏，中景草地材质，远景树线
- 沙漠：沙丘法线、风纹、色调随时段变化；修掉搜索灯光锥过曝
- 湖面：岸线和远山
- 全局：远山剪影环、高度雾、程序化云层；时段改为 6 档（清晨、正午、午后、黄昏、夜、棚拍）
- 后处理：展示模式调低颗粒和色散，并加景深“摄影模式”

## 5. 游戏模式设计

### 5.1 流程
主菜单 → **战役地图**（4 章 13 关、星级、锁）→ **简报**（地图俯视、主目标 / 次要目标、威胁、挂载、天气）→ 出击 → 任务内 HUD → **结算**（评级、星级、用时、命中、解锁）→ 下一关 / 重试 / 返回。
另设“自由挑战”：任意已解锁关卡加任意难度，成绩单独记录。

### 5.2 关卡表（数据驱动）
```js
{
  id: '3-1', chapter: 3, name: '压制防空',
  scene: { terrain: 'grass', env: 'day', weather: 'none', map: 'base' },   // map: base|town|canyon
  loadout: { gun: 1200, rocket: 38, hellfire: 8 },                          // 可减配
  threats: { sam: true, enemyAir: 0, ambush: 0 },
  objectives: [
    { type: 'destroy', tag: 'radar', label: '摧毁雷达站' },
    { type: 'destroy', tag: 'sam',   label: '摧毁防空发射车' },
    { type: 'destroy_all', label: '清剿地面目标' },
  ],
  bonus: [ { type: 'max_damage', v: 3, label: '损伤不超过 3' } ],
  fail: ['heli_down', 'fuel_out', 'timeout'],
  timeout: 360,
  stars: { two: 'B', three: 'A' },          // 评级门槛；三星还要求完成全部 bonus
  intro: '敌防空网掩护着前沿阵地……',
}
```
- 目标类型：destroy(tag)、destroy_all、rescue(n)、shoot_down(n)、survive(t)、reach(zone)、hover(zone,t)、land(zone)、protect(entity)、stay_low（不露头 / 暴露度不满）
- 失败类型：heli_down、fuel_out、timeout、protect_lost、detected
- 星级规则：★ 通关；★★ 评级达到 stars.two；★★★ 评级达到 stars.three 且完成全部 bonus
- 解锁规则：上一关 ★ 通关即解锁下一关（现在要 B，对新手太硬）；本章全部通关后解锁下一章

### 5.4 难度梯度
- 关卡本身就带难度曲线（下表 0–5 分），再乘以全局难度系数（新手 / 标准 / 老兵，沿用 83-arcade 的倍率）。

| 关 | 1-1 | 1-2 | 1-3 | 1-4 | 2-1 | 2-2 | 2-3 | 3-1 | 3-2 | 3-3 | 4-1 | 4-2 | 4-3 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 敌方反击 | 0 | 0 | 0 | 0 | 1 | 1 | 2 | 3 | 3 | 3 | 4 | 4 | 5 |
| 时间压力 | 0 | 0 | 1 | 1 | 1 | 3 | 2 | 2 | 3 | 2 | 3 | 3 | 4 |
| 资源压力 | 0 | 0 | 0 | 0 | 1 | 1 | 4 | 2 | 2 | 2 | 3 | 3 | 4 |
| 操作难度 | 1 | 1 | 2 | 3 | 2 | 3 | 2 | 3 | 4 | 3 | 5 | 4 | 5 |
- 节奏：每关只引入一个新机制；每章最后一关是本章的综合考核；第二章之后每章开头留一关“喘口气”。

### 5.5 任务内 HUD
- 左上：目标清单（勾选式），附剩余时间
- 右上：威胁区（RWR、暴露度、敌机方位）
- 下方：武器、弹药、燃油、损伤合并成一条 MFD 条
- 关键事件用中部短横幅提示（击杀、目标完成、警告），同一时刻只显示一条

## 6. 技术方案要点
- AppMode：新增模式状态（menu / show / play），挂在 HOST 上；子系统用 `enter(mode)` / `exit()` 管理装配和卸载。
- 关卡注册表：新增 91-levels（纯数据）+ 92-objectives（纯逻辑，可以用 pytest 测），由 70 层通过 HOST 注入调用，不产生反向引用。
- 现有 MISSION_VARIANTS 和 CAMPAIGN_LEVELS 迁移进关卡表；旧变体 id 保留成别名，老测试不破。
- 存档 v1 → v2：旧 6 关成绩按变体映射到新关卡 id，已解锁进度只增不减。
- 主菜单和展示分页：新增 71-launcher、73-showcase-ui；template 的面板按模式分组。
- 测试：test_launcher、test_showcase_tabs、test_levels（浏览器）+ tests_pure 加入关卡表与目标系统的纯逻辑测试；老测试先进入对应模式再跑（harness 加 `H.enter('play','2-1')`）。

## 8. 风险
- 体积：内容增加后 dist 预计 +150KB，模型仍外部加载，可接受。
- 性能：视觉提升按画质档位分级，“性能档”关掉云层和远景细节。
- 回归：模式隔离会动到很多入口，P1 先保证老测试在“游戏 → 自由模式”下照常跑。
