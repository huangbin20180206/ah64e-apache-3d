### 2.3 自动画质升档可越过 `_qCeil` 上限（本轮新发现，值得修）

**怎么发现**：读 70-hud.js:167-187 自动画质逻辑时发现状态机破口：

```js
S._qCeil = STEPS[i - 1];      // 降档时把上限压到降档前的下一档（如 1.5→1）
...
else if (S._qCool <= 0 && S._up >= 20 && i < 2 && STEPS[i + 1] <= S._qCeil) { ... }
```

**场景**：高画质降档后 `_qCeil=1`。用户此后**手动**调回"高"（`S._qManual=true`），
再切回"自动"（72-uibind.js:322 会重置 `_qCeil=1.5`，这条路没事）；
但另一条路——`pickQ('auto')` 之外，如果用户只点高级芯片而不点 auto（现 UI 无此路径，
安全）……复核结论：**现 UI 唯一切回自动的入口就是 pickQ('auto')，会重置 _qCeil**。
所以这是**理论破口，现 UI 触发不到**。

**改法决定**：不加代码（避免为不存在的路径写防御，违反精准修改纪律）。
在 `70-hud.js:174` 旁加两行注释说明"`_qCeil` 的重置仅经 72-uibind pickQ('auto')，
新增自动开关入口时必须同步重置"。
→ 验证：纯文本断言注释存在。

### 2.4 放宽 `test_no_duplicate_dbg_keys` 的窗口上限

**怎么发现**：审核 305dc4f §2.6。守护测试只扫 `__dbg` 对象前 6000 字符，
对象尾部新增 getter 脱离守护。

**改法**：窗口改为"从 `window.__dbg = {` 到下一个顶层语句"（正则截断至 `;\n` 行），
或干脆扫到文件尾但只取该对象的花括号平衡区（用 `re` 花括号配对足够）。
→ 验证：故意在尾部加重复键 → 测试变红 → 撤销 → 恢复绿（反向验证）。

## 三、P2：能力增强（可选，按精力做）

### 3.1 网络档位动态重估（接 Hark 的静态分档）

**现状**：`_GQ.MAX` 初始化时读一次 `navigator.connection`，WiFi↔蜂窝切换不重算。
**方案**：`connection.addEventListener('change', …)` 重算 MAX（该事件 Chrome 支持，
Safari 无 connection 对象——现有 try/catch 兜底已覆盖）。
**代价**：约 15 行；**收益**：弱网转强网后下载提速（GLB 共 32MB）。
**建议**：做，但排最后——开局 30 秒后网络突变属边缘场景。

### 3.2 `31-scenery.js` 告警条件的括号整理（可读性，非 bug）

`A<0 || B<0 && C<0` 补上括号成 `A<0 || (B<0 && C<0)`，语义不变，防误读。
一行改动，跟 2.1 同一个 CHANGES 记账。

### 3.3 拓扑门禁升级 tokenizer（承接上轮撤回的 P1-4）

**现状**：`undefined-global` 检查因 591 假阳性撤回。
**方案**：升级为"跳过本文件局部声明（const/let/function 参数）后再报未定义"，
先在 `tools/` 下做 1 周影子运行（只警告不失败），统计假阳性率 <5% 再转硬门禁。
**建议**：影子运行有价值（能揪出 Hark 那类重复键（部分）与真正笔误），值得排期；
但涉及约 200 行 tokenizer 改动，本轮不动，单独立项。
